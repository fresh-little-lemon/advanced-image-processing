日期：2026-10-17。阶段：工程基线与探索性机制验证。

## 完成范围

- 40 对既有探索数据：Lytro 20、EDMF 20；8 种方法/消融，320 行逐图记录
- 26 组 MFI-WHU 验证数据：9 种方法/消融，234 行逐图记录
- 程序生成的清晰目标：3 曝光 × 3 噪声 × 3 种子 × 9 方法，243 行
- 噪声估计诊断：相同 27 条件 × 4 方法，108 行

94 组 WHU 留出与 13 组 MFFW2 外部测试尚未运行。所有源图像和派生检查图在本地保存，仓库包含数值结果、配置与来源哈希。

## 验证集主要发现

26 组 WHU 的平均 PSNR：guided 37.792 dB、noise_energy 36.795 dB、去掉噪声处理 37.787 dB。当前噪声处理降低了此验证集的融合质量。

需要注意，当前 `noise_correction=False` 同时使均值扣除和权重分母中的噪声方差归零。因此这个消融只识别“耦合噪声处理”的净效果，尚不能单独归因于噪声底扣除。后续需要拆分两条路径的开关。纹理污染噪声估计是待验证机制。

## 程序生成噪声诊断

该小型诊断沿用一个固定纹理场景。在曝光比例 1 下，RGB 注入标准差与估计灰度标准差为：

| RGB 注入 σ | 理论灰度 σ（裁剪前） | 估计灰度 σA 均值 |
|---|---:|---:|
| 0 | 0 | 0.001609 |
| 0.01 | 0.006686 | 0.014340 |
| 0.03 | 0.020057 | 0.031207 |

独立 RGB 高斯噪声转换至灰度时采用 `σ × sqrt(.299²+.587²+.114²)`；裁剪后该公式不再给出精确协方差。

相同条件下，σRGB=0.03 时 guided / 估计噪声 energy / oracle 噪声 energy 的平均 PSNR 为 30.486 / 31.004 / 30.639 dB。当前估计有偏，同时某一受控条件下的偏差仍可能偶然改善最终输出；应结合能量误差、可靠性校准和不同纹理分层解释。该结果也说明不能把单一清晰验证集的退化直接推广为所有噪声条件的结论。

## PC 计时

Intel Xeon Platinum 8573C，x86-64，520×520，限制 1 线程。核心融合中位数（毫秒）：

| 方法 | Python | C++ |
|---|---:|---:|
| average | 19.26 | 4.73 |
| laplacian | 34.52 | 13.64 |
| sml | 33.71 | 15.63 |
| guided | 124.31 | 158.96 |

Python 预热 2 次、重复 7 次；C++ 预热 3 次、重复 10 次。两者排除文件解码与写出，但包含各自 API 的验证和内存分配。C++ guided 使用直接的反射边界中值实现，尚待性能优化。共享云 CPU 上存在调度波动；原始重复值和进程 RSS 见结果 JSON。ARM64 的真实测量待设备/CI运行。
