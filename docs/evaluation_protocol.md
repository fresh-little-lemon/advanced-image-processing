# 传统多聚焦融合评测协议 v1

冻结日期：2026-10-17。本文定义实验方法与验收条件。运行报告使用“已实现、已执行、待执行、阻塞”四类状态。

## 1. 问题和比较对象

输入为同一场景的不同焦点图像；输出为尽可能清晰且辐射外观一致的单幅图像。曝光差、传感器噪声和轻微错位是鲁棒性因素，不引入深度学习模型或学习型质量指标。

比较组至少包括：简单均值、固定SML/梯度择优、两层guided-filter融合、Laplacian pyramid融合，以及完整候选算法。论文复现基线必须注明作者代码/重实现、版本、参数、边界策略和是否完成数值对照；受GFF启发的实现统一标为GFF-inspired，作者实现另列。应同时保留曝光归一化开/关、噪声估计开/关、置信度开/关、细化开/关的组件消融。

对计算分配的公平比较：全图廉价路径、全图昂贵路径、随机tile、仅边界tile、置信度tile。预算按实际CPU时间或相同细化像素数分别匹配；两种预算结果分开报。随机分配至少5个固定种子；各方法共享同一输入扰动。保留先前EDMF归一化分支较差的负结果，并同时列出正向与负向变化。

## 2. 输入与预处理约定

原始文件保留不变。主要自然图像评测在原生分辨率进行；性能压力测试另设640×480、1280×720、1920×1080的固定画布。缩放仅用于单独压力测试，与原生质量分表汇总。

解码为RGB，明确JPEG解码库版本。亮度主通道固定 `Y=0.299R+0.587G+0.114B`，范围[0,1]，质量计算用float64。算法可以float32，但需单独记录精度。sRGB域与线性光域分别命名：主终点使用已知线性光度扰动轨道：标准sRGB逆变换，统一clean full_clear辐射尺度，输出映回同一线性尺度后计算PSNR-Y；SSIM为次终点。sRGB PSNR/SSIM仅作单独补充，与线性域数值分别汇总。未知真实曝光且没有辐射GT的图像不计算该主终点。

全部方法共用相同预处理及有效区域。亮度校正和后处理采用所有方法共享的设置。预处理、配准、归一化和颜色重建计入端到端算法耗时；磁盘解码计入单独I/O轨道。若配准失败，保留失败状态、时间、失败率和回退结果。

## 3. 全参考质量与可解释误差

### 3.1 MFI-WHU提供的full_clear

按每组同编号full_clear计算：

- PSNR-Y：MSE在有效区域线性光亮度上平均，数据范围1（clean GT的固定标度，所有方法共享标度），`10 log10(1/MSE)`；MSE=0记正无穷并另报次数
- SSIM-Y：11×11高斯窗、σ=1.5、K1=.01、K2=.03、L=1、总体协方差，valid窗中心区域；报告所用库与参数，显式设置全部参数
- RGB PSNR作为颜色补充，不代替主亮度指标；颜色偏移使用平均RGB绝对误差，若增加ΔE则必须注明Lab白点与转换
- 边缘误差：GT亮度Sobel梯度幅值最高10%像素集，比较输出与GT的梯度幅值MAE（阈值只由GT决定）
- 强度裁剪率：输出在[0,1]端点的像素比例；同时报相对GT新增的裁剪比例

WHU未提供可验证的原始焦点mask，因此按GT局部重建误差定义的标签记为重建oracle。可以补充 oracle-source-error：对A/B与GT的7×7局部MSE较小者定义重建oracle，差值≤(1/255)^2区域不评分；它测量择优是否匹配重建oracle；物理焦点标签另设验证轨道。

### 3.2 有确切生成mask的独立合成轨道

生成器保存GT、mask、模糊PSF、边界合成顺序及种子。基础轨道以WHU full_clear为纹理源，继承该场景split：mask由固定种子的直线/圆/多边形与细线构成；背景/前景互补模糊σ∈{1,2,4}像素，核半径ceil(3σ)。至少分别实现“先整图模糊再mask拼接”和“前后景分层遮挡后模糊”轨道；前者标为mask拼接模型，真实DSE对应分层遮挡轨道。

mask边界半径r=ceil(3σ)内定义不确定带；分别报带内/带外PSNR、选择错误率。选择错误率仅在两个潜在源清晰度有可辨识差异且未饱和的位置统计，权重图以wA≥.5转A，平局固定为A。纹理平坦且两源相同的像素归入不可辨识区域。

置信度评价：ECE使用验证阶段固定的10个等宽bin，报告每bin样本数、准确率与平均置信度；另报Brier score、风险-覆盖率曲线与AURC。训练/校准仅用验证场景，所有变体与场景一起隔离。置信度如果不是概率，只做排序风险评价，概率校准另设评估。

halo采用可核验的测试卡轨道：锐利台阶/细线GT，记录边缘两侧5像素带中的overshoot与undershoot相对台阶幅值、最大值及95分位。自然图像只报“边界重建误差/梯度误差”，真实无GT图像的halo通过固定ROI审查。

## 4. 真实图像的互补指标

MFFW2没有本次下载的可信全清晰GT；全参考PSNR仅用于有GT的轨道。主证据由输入/输出成组展示、固定边界ROI、Q_AB/F和失真诊断构成。

Q_AB/F采用Xydeas–Petrovic原定义，记录Sobel方向、卷积边界、梯度权重L=1、零梯度规则及logistic常数。公开常用MATLAB实现参数为Tg=.9994、kg=-15、Dg=.5、Ta=.9879、ka=-22、Da=.8。实现来源：https://www.mathworks.com/matlabcentral/fileexchange/18213-objective-image-fusion-performance-measure 。原论文DOI：https://doi.org/10.1049/el:20000267 。现有简化梯度比分数若没有完整方向和logistic部分，标为proxy，完成上述公式与数值对照后再列入Q_AB/F结果。

验证门槛：

1. 独立参考实现与生产实现对相同float64测试图对照，明确内部卷积/相关是否一致；固定5个非平坦图样和至少3组验证图，目标绝对误差≤1e-8（相同边界/浮点算法）
2. 检查交换A/B不变性、全平图零梯度处理无NaN、输出尺寸与RGB转换一致、水平/垂直/斜线方向的行为
3. 输入与输出相同的自一致case分数不是必然精确1：logistic顶点常数会造成上限小于1；原指标按上述定义保留其数值范围
4. 记录指标测试报告和代码哈希。验证状态分为公式实现、单元测试通过、独立参考数值对照通过

补充指标至少含Q_CB或结构型融合质量中的一种及MI(A,F)+MI(B,F)。MI固定64个等宽bin，[0,1]范围，联合概率按像素计数，以log2计算；横向比较使用一致直方图设置。补充指标若尚未实现则显式留空，不填估算。它们是互补诊断；各指标分别报告，不设综合名次。

曝光扰动下Q_AB/F和MI可能偏向某输入的亮度/对比度，因此同时报告：与扰动前clean inputs比较的Q_AB/F（受控仿真实验）、与实际扰动inputs比较的Q_AB/F（部署诊断）、饱和率和亮度漂移。两者独立命名，两列均完整保留。对真实已曝光不一致且无clean inputs的数据，保留指标偏倚说明并重视固定ROI盲评；鲁棒性结论综合重建、边界、失真与效率证据。

## 5. 可复现扰动与全因子实验

计算规模分为screen和confirm。screen只在验证集选择参数。confirm在冻结测试集进行以下完整27格：

- 曝光差e∈{-1,0,+1}EV：固定A不变，B在线性RGB各通道乘2^e；最后统一clip
- 高斯读出噪声σ∈{0,5,15}/255：A、B独立采样，两个输入均加噪；确认主轨道在线性光域；另列sRGB编码域压力测试，不混合汇总
- 位移d∈{0,.5,1.5}像素：B沿x方向平移d，双线性采样；记录共同有效区域并从所有指标中排除无效插值边界

每格噪声种子为字符串 `v1|scene_id|e={e}|sigma={sigma}|shift={d}|repeat={repeat}` 的SHA-256前16位十六进制转uint64，随机生成器固定NumPy PCG64，repeat=0,1,2；A/B按固定顺序从同一生成器依次取样；无噪声格只算一次，汇总不因重复相同样本增权。源顺序交换作为单独对称性检查，不与方向因素混淆。退化顺序固定为解码→sRGB逆变换→曝光→加噪→位移→clip→sRGB编码→量化（同一实验仅在最终量化一次），保存配置与生成器版本。clean baseline为e=0,σ=0,d=0。

范围外压力检查另列：±2EV、σ=25/255、2像素平移、±.5°旋转、shot+read Poisson-Gaussian噪声、JPEG质量70。shot噪声必须用明确光子/电子增益，例峰值1000与250电子、read σ=2电子，明确记录噪声物理参数。范围外结果不回流调参，不与27格平均混合。

各因素的主效应、二阶交互与全条件宏平均均报，并列每数据集clean退化量。把某一个光照条件或单一噪声强度的最好结果描述成全局鲁棒是不成立的。

## 6. 统计汇总

先在每个scene内平均种子与固定条件，再在scene间宏平均，独立统计单位为场景而非像素或重复条件。报告均值、中位数、最差10%场景均值、失败数；对候选与强基线用同场景配对差值。置信区间用scene/group级bootstrap，固定种子20261017、10,000次、95%区间。MFFW仅13组，强调区间和逐例结果，以区间和逐例差值解释结果。

所有基线同一预算、输入、质量ROI。每个消融给出准确度/重建质量变化与时间变化，报告负结果。运行结果按test、validation、external_test与exploration分表。

## 7. PC与嵌入式性能

统一C++接口和输出语义；PC和ARM用同一算法提交与冻结配置，不要求相同指令实现。必须记录CPU型号/架构、OS、编译器及版本、编译flags、OpenCV/数学库版本、线程数、CPU affinity、频率策略、精度、输入尺寸、功耗模式与温度。

主要延迟测试：单线程CPU、GPU关闭，关闭隐式OpenCV/BLAS线程；预先解码输入，预分配可复用缓冲，warm-up 20次，再对固定场景轮转测量至少100次（每次完整算法），保存每次原始时长。另测固定4线程配置，同一比较表使用相同线程配置。采用单调时钟，P50和P95用固定nearest-rank定义；报告均值、标准差和P99作为补充。

另外报告冷启动首次调用、含解码的端到端延迟、峰值RSS与工作缓冲字节。RSS在隔离子进程测，注明包含运行时/库内存；既报绝对峰值也报基线空进程差值。Linux ru_maxrss单位KiB，其他平台核实单位后换算。能耗仅在真实仪器或可信板载传感器采样时报告，每帧焦耳说明采样区间；未采样时能耗字段记为待测。

ARM连续运行至少10分钟，比较前后P95与温度，记录热降频；有deadline的产品目标必须在实验前定义，例如720p P95≤33.3ms、峰值内存≤256MiB列为预设目标，实测结果单列。优先给出质量—P95—内存Pareto曲线，辅以FPS。

验证等级分开：L0=接口与单元测试；L1=x86真实运行；L2=ARM交叉编译与静态产物检查；L3=真实ARM执行与数值一致性；L4=真实ARM长时性能/热稳定/能耗。QEMU用于功能补充；真实板端延迟从L3开始记录。Python原型时间和优化C++时间分开，同语言、同硬件实现之间计算加速倍数。

float32/float64/定点分别验收，记录相对float64的最大绝对误差、均值误差、PSNR变化、mask分歧率。编译fast-math或SIMD近似必须通过这些检查。具体允差先在验证集固定，默认像素输出max abs≤1/255、平均abs≤0.1/255；不满足时说明精度变化并保留原允差。
